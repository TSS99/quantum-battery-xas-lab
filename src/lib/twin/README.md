# Beamline twin (`src/lib/twin`)

A quantitative XAS beamline simulator: source, mirrors, double crystal monochromator, ion chambers, sample and
environment, fluorescence detector and scan engine. The `/twin/` page, the headless CLI and the MCP server all use
these modules. The full plan is in the runner folder (`PLAN-beamline-twin.md`); this file holds the rules that keep
parallel work consistent.

## Rules
1. **Pure TypeScript.** No DOM, React or browser APIs in `src/lib/twin`, so the code runs in a Web Worker and in Node.
2. **Types come from `types.ts`.** Extend it rather than redefining shapes. Units are in property names (`_eV`, `_um`...).
3. **Deterministic.** Randomness only through a seeded generator passed in (see `seededRandom` in `src/lib/xas.ts`);
   the same seed and state give identical results.
4. **Data from tables, not constants.** Physical data comes from `src/data/twin/*.json` (generated by
   `scripts/twin/*.py` from xraydb and Larch, with the exact calls recorded) or from the existing `src/lib/xraydata.ts`.
   Do not type physical constants or table values by hand unless they are exact definitions (for example hc or the Si
   lattice constant) with a cited source in a comment.
5. **Golden tests.** Every model has a vitest test against fixtures produced by the reference libraries
   (`src/data/twin/fixtures.json`, `src/data/twin/feff-fixtures.json`) with the tolerance from the plan (section 4.4).
6. **Provenance.** Functions that return curves also return their `Provenance`. Teaching models are labelled as such.
7. **Small, lazy data.** Optics tables at most 150 KB gzip in total; FEFF path sets and XANES spectra load per material.

## Modules
`types.ts` contract · `tables.ts` data loading and interpolation · `source.ts` · `mono.ts` · `mirrors.ts` · `beam.ts` ·
`chambers.ts` · `sdd.ts` · `sample.ts` · `damage.ts` · `exafs.ts` · `xanes.ts` · `scan.ts` · `acquire.ts` · `xdi.ts` ·
`calibrate.ts` · `scenarios.ts` · `telemetry.ts` · `explain.ts` · `twin.ts` (facade) · `worker.ts`.

`exafs-fit.ts` fits explicit FEFF shells in k or R space with bounded parameters,
affine links and Larch-scaled covariance. See [EXAFS_FITTING.md](EXAFS_FITTING.md)
for the API, units, independent-point conventions and reproducible checks.
